# MSPM0G3507 模块化循迹工程

工程名：`mspm0g3507_lineTracker`

版本：`2.2.1`

稳定算法基线标签：`line-tracker-v2.0`

实车状态：八路灰度循迹、普通弯道和左右直角弯已经通过当前车辆实测。

这是根据稳定参考工程重新整理的全新版本。它保留参考工程中已经验证过的：

- 八路灰度加权位置误差；
- 真正的PD控制；
- 根据偏离程度动态降低基础速度；
- 普通循迹时不让车轮反转；
- MPU6050角速度阻尼；
- 直角弯离开旧线/重新捕获新线两阶段。

同时按新版讨论确定了六个运行状态：

| 编号 | 名称 | 说明 |
|---:|---|---|
| 0 | 停车 | 上电、自检失败、故障和待启动 |
| 1 | 直线循迹 | 正常位置PD和动态速度 |
| 2 | 自主直行 | 起步全白时按陀螺仪方向直行 |
| 3 | 弯道循迹 | 圆弧、S弯，不是直角弯 |
| 4 | 左直角弯 | 连续差速保线并寻找新线 |
| 5 | 右直角弯 | 连续差速保线并寻找新线 |

## CCS导入和编译

在 CCS 中导入：

```text
ticlang/mspm0g3507_lineTracker_LP_MSPM0G3507_nortos_ticlang.projectspec
```

项目目标是 MSPM0G3507、TI Arm Clang、MSPM0 SDK 2.11。SysConfig源文件是：

```text
mspm0g3507_lineTracker.syscfg
```

不要手工修改 `Debug/` 或 `build/` 中生成的 `ti_msp_dl_config.c/.h`。

2.0 已完成源码检查、CCS 编译和实车验证，并作为不可随意改动的控制算法基线。
2.0.1 修复了上电时OLED初始化时序。2.0.2进一步修复自主直行发现斜线、
偏线或过宽连续黑线时的状态切换；循迹PD和直角弯控制本身不变。
2.1.0提高了状态1进入状态3的可信度：必须经过1 s门控、灰度不再是直线形态，
并且同方向Yaw角速度达到30 °/s且连续保持240 ms。直线纠偏造成的短时左右摆动
会重新计时，不再轻易累计成弯道。OLED同时改为事件式刷新，运行时不再周期刷整屏。
2.2.0改为直接根据灰度偏离进入状态3：X2+X3、X6+X7或更外侧的同向偏离必须
持续500 ms，回中或换边都会重新计时。X3+X4、X5+X6仍保持状态1，并增加专门的
近中心快速修正量，让车辆在只偏一格时就主动回中。
2.2.1在保持2.2.0状态切换逻辑的基础上，成比例提高直线、偏移、弯道、自主直行
和直角转弯速度；同步提高状态1/3的P、D、近中心修正和修正上限。状态1对误差
绝对值2或3立即加强拉回，回到中心时由D项提供反向制动，减少二次摆动。

上电后程序会自动点亮OLED并执行自检，随后停在状态0等待K1；RST仅保留为
芯片卡死时的硬件复位键，不承担启动或模式切换功能。当前K1负责启动、K4负责
运行中紧急停车，K2/K3保留给后续功能。

## 蜂鸣器反馈

- 自检通过：1声短鸣。
- K1进入状态1：1声短鸣。
- K1进入状态2：2声短鸣。
- 左直角开始：4声短鸣。
- 右直角开始：5声短鸣。
- 自检、丢线、非法灰度、转弯超时等故障：1声长鸣并回到状态0。

OLED采用事件式输出：状态切换时只更新第一行的状态和故障码；进入状态0或发生
故障时才完整显示原始灰度、位置误差、PD输出、左右速度、Yaw和Yaw角速度。
运行中不再每100 ms刷新整屏，避免约30 ms的I²C传输打断20 ms控制节拍。
OLED无响应时只关闭调试输出，不会修改循迹控制路径。

## OLED故障码对照表

OLED第一行的 `FAULT` 数字来自状态机的实际故障枚举：

| FAULT | 代码名称 | 含义和触发条件 |
|---:|---|---|
| 0 | `APP_FAULT_NONE` | 没有故障，状态0只是正常停车或等待K1启动。 |
| 1 | `APP_FAULT_SELF_TEST` | 关键模块自检失败。当前关键模块是电机驱动和MPU6050；OLED故障本身不会阻止车辆运行。 |
| 2 | `APP_FAULT_START_PATTERN` | 状态0按K1时灰度图案不允许起步，例如全黑或离散黑点。全白会正常进入状态2，连续黑线会进入状态1。 |
| 3 | `APP_FAULT_LINE_LOST` | 状态1或状态3运行中连续全白达到300 ms，表示黑线长时间丢失。 |
| 4 | `APP_FAULT_LINE_INVALID` | 状态1或状态3运行中全黑或离散图案持续达到120 ms。连续但较宽的黑线在2.0.2中不再触发此故障。 |
| 5 | `APP_FAULT_MOTOR_COMM` | 向电机驱动板发送速度或停车命令时软件I²C通信失败，应检查PA12/PA13、共地、电机板供电和地址0x26。 |
| 6 | `APP_FAULT_IMU` | 车辆运行时MPU6050读取失败，应检查PA1/PA0、3.3 V、GND和地址0x68。 |
| 7 | `APP_FAULT_FREE_RUN_TIMEOUT` | 状态2自主直行超过30 s仍未连续捕获可加权的黑线。 |
| 8 | `APP_FAULT_LEFT_CORNER` | 左直角弯在12 s内没有重新捕获新线，或者累计转角达到360°安全限制。 |
| 9 | `APP_FAULT_RIGHT_CORNER` | 右直角弯在12 s内没有重新捕获新线，或者累计转角达到360°安全限制。 |
| 10 | `APP_FAULT_EMERGENCY_STOP` | 车辆运行时按下K4，程序执行紧急停车并返回状态0。 |

故障发生后车辆会立即回到状态0。排查时应同时查看 `FAULT`、`RAW`、模块状态
`M/L/O/I` 和MPU6050状态 `S/W`，不要只根据蜂鸣次数判断。

## 首次测试顺序

1. 只接核心板和DAPLink，先确认工程能编译。
2. 架空车轮，接电机驱动和电池，按K1验证左右轮方向。
3. 灰度位序需要复查时使用单独的传感器测试工程；正式循迹程序不再实时刷新 `RAW`。
4. 保持MPU6050静止完成2秒预热和400次校准。
5. 低速测试状态1直线，再测试状态3和左右直角。
6. 所有状态通过后再落地到尼龙布场地。
