# MSPM0G3507 模块化循迹工程

工程名：`mspm0g3507_lineTracker`  
版本：`2.0`  
Git 标签：`line-tracker-v2.0`  
实车状态：八路灰度循迹、普通弯道和左右直角弯已经通过当前车辆实测。

这是根据稳定参考工程重新整理的全新版本。它保留参考工程中已经验证过的：

- 八路灰度加权位置误差；
- 真正的PD控制；
- 根据偏离程度动态降低基础速度；
- 普通循迹时不让车轮反转；
- MPU6050角速度阻尼；
- 直角弯离开旧线/重新捕获新线两阶段。

同时按新版讨论确定了六个运行状态：

| 编号 | 名称 | 说明 |
|---:|---|---|
| 0 | 停车 | 上电、自检失败、故障和待启动 |
| 1 | 直线循迹 | 正常位置PD和动态速度 |
| 2 | 自主直行 | 起步全白时按陀螺仪方向直行 |
| 3 | 弯道循迹 | 圆弧、S弯，不是直角弯 |
| 4 | 左直角弯 | 连续差速保线并寻找新线 |
| 5 | 右直角弯 | 连续差速保线并寻找新线 |

## 接线

| 模块 | 引脚 | MSPM0G3507 |
|---|---|---|
| 电机驱动软件I²C | SCL/SDA | PA12/PA13 |
| 八路灰度 | OUT | PA14 |
| 八路灰度选通 | AD0/AD1/AD2 | PA15/PA16/PA17 |
| MPU6050软件I²C | SCL/SDA | PA1/PA0 |
| MPU6050地址 | AD0 | 接GND，地址0x68 |
| OLED硬件I²C0 | SCL/SDA | PA31/PA28 |
| 按键 | K1/K2/K3/K4 | PA2/PB19/PB20/PA23 |
| 蜂鸣器 | PWM | PB24 / TIMA0 CCP3 |
| 状态灯 | 蓝/绿 | PB2/PB3 |

电机映射保持已经实车确认的版本：

```text
M1 = 左前，发送 left
M2 = 右前，发送 -right
M3 = 左后，发送 -left
M4 = 右后，发送 right
```

## CCS导入和编译

在 CCS 中导入：

```text
ticlang/mspm0g3507_lineTracker_LP_MSPM0G3507_nortos_ticlang.projectspec
```

项目目标是 MSPM0G3507、TI Arm Clang、MSPM0 SDK 2.11。SysConfig源文件是：

```text
mspm0g3507_lineTracker.syscfg
```

不要手工修改 `Debug/` 或 `build/` 中生成的 `ti_msp_dl_config.c/.h`。

2.0 已完成源码检查、CCS 编译和实车验证，并作为当前稳定版本保存。

## 蜂鸣器反馈

- 自检通过：1声短鸣。
- K1进入状态1：1声短鸣。
- K1进入状态2：2声短鸣。
- 左直角开始：4声短鸣。
- 右直角开始：5声短鸣。
- 自检、丢线、非法灰度、转弯超时等故障：1声长鸣并回到状态0。

OLED调试页显示状态、故障码、原始灰度、位置误差、PD输出、左右速度、Yaw和
Yaw角速度。OLED无响应时只关闭调试输出，不会修改循迹控制路径。

## 首次测试顺序

1. 只接核心板和DAPLink，先确认工程能编译。
2. 架空车轮，接电机驱动和电池，按K1验证左右轮方向。
3. 单独观察OLED上的 `RAW`，确认X1在车左、X8在车右，并核对黑线有效电平。
4. 保持MPU6050静止完成2秒预热和400次校准。
5. 低速测试状态1直线，再测试状态3和左右直角。
6. 所有状态通过后再落地到尼龙布场地。
